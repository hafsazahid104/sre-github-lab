# sre-github-lab
## Overview 
Study the clients hiring and recruitmnet system of coding pixels and identify gaps.
## Scope 
- In scope: CV shortlisting against basic requirements: already automated through an existing ATS. 
- In scope:  Technical interview scheduling and feedback (1-2 rounds, with department leads). .
- In scope: Backgorund verfication of the candidate. 
- Out of scope: Project and task management already handled by Asana, Click Up, and Jira. . 
- Out of scope: Final hiring decisions stay with humans. . 
## Stakeholders 
- HR: Post job and collect CVs.
- candidates: apply through portals, email an docs. 
- Deapartment leaders: raise vacancies with skills  needed.
## Functional requirements 
- FR-01: The system shall recieve CVs and application in one place. 
- FR-02: The system shall Reference checks with previous companies. 
- FR-03: The system shall  keep Intern records so interns can be hired quickly in an emergency. 
## Nonfunctional requirements 
- NFR-01: The system shall recieve  1000 applications without slowing down. 
- NFR-02: The system shall be available 99 percent of the time during working hours. 
## Acceptance criteria 
- FR-01: Reduce the time spent on screening calls and post-shortlist coordination by 20% within few weeks.
- FR-02: Reduce intern response time from the current 1-2 weeks to few days 
- FR-03:  Strong candidates are saved and can be found when a matching vacancy opens 
## Assumptions and open questions 
- Assumption A-01:  Will this sytem works fine with the existing system.
- Question Q-01: Good candidates get lost due to seats unavailability.
- Question Q-02: Interns hiring in peak seesion will test NFR-01.
